# StudyPal

Exam prep for NEET, JEE and board students: upload a textbook chapter and read it
with the definitions, concepts and facts already highlighted on the real page.
Highlighting runs on Gemma, an open-weight model you host yourself, on your own
machine or on a server (see [Deploy on Render](#deploy-on-render)). No per-page API fees.

```
PDF → numbered sentences + line positions → Gemma picks key sentence ids → highlights drawn on the page
```

| Colour | Type |
|---|---|
| Yellow | key concept |
| Blue | definition |
| Green | fact / formula |
| Pink | example |

## Run the app

```bash
pip install pymupdf requests fastapi "uvicorn[standard]" python-multipart
llama-server -hf ggml-org/gemma-3-4b-it-GGUF --port 8080   # optional: rules are used without it
cd web && npm install && npm run build && cd ..            # builds the UI into static/
uvicorn server:app --port 8000                             # open http://127.0.0.1:8000
```

Working on the UI: run `npm run dev` in `web/` (hot reload on :5173, API proxied to :8000).

| Path | What |
|---|---|
| `server.py` | FastAPI: upload, page highlights, progress; serves the built UI |
| `web/` | React + TypeScript + Tailwind + Framer Motion; PDF.js renders the real page |
| `data/` | uploaded books and the SQLite cache (`STUDYPAL_DATA` to move it) |

## Command line

```bash
pip install pymupdf requests pytest

# 1. Start a local model (llama.cpp). Downloads ~2.5 GB once; use gemma-3-1b-it-GGUF for a ~800 MB model.
llama-server -hf ggml-org/gemma-3-4b-it-GGUF --port 8080

# 2. Highlight a chapter
python highlight.py ncert_biology_ch6.pdf --pages 1-10
```

Output: `<name>_highlighted.pdf` (open in any PDF reader) and `<name>_highlighted.json`
(every sentence, its rectangles and the highlights, for the web reader to draw later).

No model running? It falls back to a rule-based scorer automatically, which is also
the baseline Gemma is compared against. Point at another server with
`STUDYPAL_LLM_URL=http://host:port/v1/chat/completions` (plus `STUDYPAL_LLM_KEY` if it
needs an API key), or set `STUDYPAL_LLM_URL=` (empty) to use the rules only.

## Deploy on Render

[`render.yaml`](render.yaml) is a Blueprint for two services in Singapore:

| Service | What | Plan |
|---|---|---|
| `studypal-gemma` | Gemma 3 4B on llama.cpp ([`llm/Dockerfile`](llm/Dockerfile)), CPU only, API key generated by Render | `2c-4g` (`4c-8g` is ~2x faster) |
| `studypal` | The app ([`Dockerfile`](Dockerfile)): React UI + FastAPI, 1 GB disk for books and the cache | `0.5c-512mb` |

In the Render Dashboard: **New → Blueprint**, pick this repo, approve. The app reaches
Gemma over Render's private network. While Gemma is still booting, pages get rule-based
highlights, and they're redone with Gemma once it's up.

To use the hosted model while developing locally:

```bash
STUDYPAL_LLM_URL=https://<studypal-gemma URL>/v1/chat/completions \
STUDYPAL_LLM_KEY=<LLAMA_API_KEY from the Render dashboard> \
uvicorn server:app --port 8000
```

## Design choices

- **The model returns sentence ids, never quoted text.** Small models misquote; ids can't
  be misquoted, and invalid or repeated ids are dropped before drawing.
- **Grammar-constrained JSON** (llama.cpp `response_format` with a schema): every reply
  parses, the id field only accepts ids that exist on the page, and `maxItems` caps
  highlights per page (asked nicely, Gemma 3 4B marked 63% of a chapter).
- **Sentence splitting from layout, not blocks.** PDFs don't store sentences, and some
  store every line as its own block. Splits happen on punctuation, heading-sized lines
  and paragraph gaps, so a sentence that wraps across lines stays whole.
- **Scanned PDFs are detected** and rejected with a clear message (OCR comes later).

## Files

- `extract.py` — sentences with ids and rectangles
- `keypoints.py` — Gemma picker + rule baseline
- `highlight.py` — runs the pipeline, writes PDF + JSON
- `book.py` — processes a book 30 pages at a time, ahead of the reader
  (`python book.py book.pdf --goto 26`)
- `store.py` — SQLite cache (`studypal.db`), so each page is processed once
- `tests/` — `python -m pytest -q tests` (11 tests; no model needed)

## Long books

Nothing is processed up front beyond pages 1–30. The reader calls `visit(page)` on
every page turn: the chunk holding that page goes first, reaching page 25 of a chunk
starts the next one, and the most recent visit always wins, so jumping to page 400
serves page 400 next. Pages are saved one at a time, so highlights appear while a
chunk is still running.
